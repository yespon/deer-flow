🎯 关键设计决策

1. 多租户隔离模式

决策: 支持 strict 和 relaxed 两种模式
原因: 满足不同企业安全要求，从共享实例到完全隔离
实现: Schema 隔离 vs 行级安全策略

2. Agent Teams 编排策略

决策: LLM 驱动的动态编排 + 预定义模板
原因: 平衡灵活性和可预测性
实现: TaskDecomposer 生成计划，AgentRegistry 分配执行者

3. Human-in-Loop 架构

决策: 状态机驱动的挂起/恢复机制
原因: 支持长时间审批流程，不阻塞运行时
实现: ApprovalStateMachine + 持久化队列

4. 审计不可篡改

决策: 事件签名 + 链式哈希
原因: 满足企业合规审计要求
实现: Ed25519 签名，审计日志只追加

⚠️ 风险与缓解策略

风险 1: 多租户数据泄露
缓解: 自动化集成测试覆盖所有边界情况，定期安全审计
风险 2: HIL 状态丢失
缓解: 持久化状态机，消息队列确保投递，死信队列处理失败
风险 3: Agent Teams 无限递归
缓解: 层级限制，Token 预算，循环检测中间件
风险 4: 配额绕过
缓解: 配额检查在所有入口点，分布式计数器，硬限制优先
